# 契约以代码与测试为准，模块文档只写取舍与坑

`docs/modules/<模块>.md` 不列 API 签名、请求形状、字段与默认值、行为步骤；这些事实由源码与对应测试承载。模块文档只留三类内容：跨模块的取舍与理由、外部系统与平台的坑、指向源码与测试的指针。`docs/ARCHITECTURE.md` 的模块表是模块文档的唯一索引，根 README 不列模块文档。

理由：同一事实曾有三份副本（源码、模块文档、README / CHANGELOG），改一处必漏两处。测试守住形状，`check-imports` 守住依赖方向，文档再抄一遍只增加漂移面。代价是读文档不再直接看到请求形状，需跳一次源码；用指针与测试文件名补入口。

不做的：从代码生成模块文档（typedoc / JSDoc 导出）、把契约搬进 ADR。理由：生成器要新增依赖与维护；ADR 只记取舍与理由，放契约会让决策记录随实现漂移。
